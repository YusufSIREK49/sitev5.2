Dify Stüdyo Mimarisi ve 3'lü Model Görev Dağılımı

BTÜ Geçerken ekosisteminde çalışan tüm yapay zekâ yetenekleri, Docker üzerinde barındırılan açık kaynak Dify LLM Orchestration stüdyosu üzerinden yönetilmektedir.

Neden Çoklu Model Mimarisi? Tek bir yapay zekâ modeline tüm ekosistem görevlerini yüklemek bağlam kirliliğine, yüksek gecikmeye ve kota tıkanmalarına yol açar. Bu nedenle sistem 3 farklı uzman modele bölünmüştür.

2. Kota ve Yoğunluk (High Demand) Koruması

Özellikle sayfa içi asistanın yoğun anlarda Google AI Studio tarafındaki high demand (503/429) hatasına takılmasını engellemek için iki aşamalı optimizasyon kuralı uygulanır:

  • Maksimum Token Sınırı: Dify model parametrelerinde Max Tokens değeri 1024 olarak sınırlandırılır; böylece model baştan devasa hesaplama yükü rezerve etmez.
  • Gövde Kırpma (Context Trimming): script.js sayfa içeriğini toplarken karakter sayısını 1800 ile sınırlandırır; gereksiz HTML etiketlerini ve boşlukları temizler.

Sayfa İçi Asistan ve Dinamik Bağlam Yakalama

Kullanıcı bir blog yazısına veya etkinlik detayına girdiğinde sağ altta beliren asistan, genel bir sohbet botu değil; doğrudan içinde bulunduğu sayfayı okuyan bir yapay zekâdır.

1. Otomatik Sayfa Metni Çıkarma Algoritması

Sayfa açıldığında script.js makalenin başlığını ve ana gövdesini DOM üzerinden dinamik olarak toplar:

function collectPageContext() {
  const titleEl = document.querySelector('h1') || document.title;
  const contentEl = document.querySelector('.blog-content') || 
                    document.querySelector('article') || 
                    document.body;

  const title = typeof titleEl === 'string' ? titleEl : titleEl.innerText;
  const rawText = contentEl.innerText.replace(/\s+/g, ' ').trim();
  
  // Kota koruması için en can alıcı ilk 1800 karakteri bağlam yapar:
  const trimmedText = rawText.slice(0, 1800);

  return { title, content: trimmedText };
}

Farabi AI Portalı, Streaming ve Dosya Analiz Motoru

Farabi AI, klasik soru-cevap asistanlarının ötesinde, tam ekran arayüzü ve gelişmiş veri işleme yetenekleriyle bağımsız çalışan bir platformdur.

1. SSE Streaming (Server-Sent Events) Akış Mimarisi

Model yanıtlarının daktilo efektiyle parça parça ve gecikmesiz akması için Dify'ın response_mode: "streaming" protokolü kullanılır:

// Farabi AI SSE Okuyucu Hattı (app.js)
const response = await fetch('/api/dify-farabi/chat-messages', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(payload)
});

const reader = response.body.getReader();
const decoder = new TextDecoder('utf-8');
let fullAnswer = '';

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  const chunk = decoder.decode(value, { stream: true });
  const lines = chunk.split('\n');

  for (const line of lines) {
    if (line.startsWith('data: ')) {
      const json = JSON.parse(line.slice(6));
      if (json.event === 'message' || json.event === 'agent_message') {
        fullAnswer += json.answer || '';
        onChunk(fullAnswer); // UI'ı her harfte anında günceller
      }
    }
  }
}

2. Yerel Dosya Yükleme ve Analiz Hattı

Kullanıcı ataç butonuna basarak bir PDF, DOCX, tablo veya görsel seçtiğinde, dosya doğrudan Nginx proxy'si üzerinden Dify dosya havuzuna iletilir:

  1. İstemci dosyayı FormData formatında Nginx'in /api/dify-farabi/files/upload rotasına postalar.
  2. Dify dosyayı sunucuya kaydeder ve geriye benzersiz bir upload_file_id döndürür.
  3. Ardından gönderilen ilk mesajın files dizisine bu ID eklenerek modelin belgeyi bağlam olarak okuması sağlanır.

3. Akıllı Başlıklandırma ve Yerel Depolama (LocalStorage)

Tüm oturum geçmişi kullanıcının kendi cihazında (localStorage) saklanır; böylece sunucuda gereksiz kullanıcı veritabanı tutulmaz. İlk mesaj iletildikten sonra Dify arka planda asenkron olarak 3-4 kelimelik kısa ve net bir sohbet başlığı türeterek sol kenar çubuğuna işler.
